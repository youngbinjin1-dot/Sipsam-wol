## 2. 단계별 산출물 요약

### 01 시장 신호 — PEST
| 구분 | 핵심 신호 |
|---|---|
| Political | 세무사법·AI 기본법·마이데이터 확대, 매년 바뀌는 공제율·한도 |
| Economic | 고물가 속 예상 못한 추가 납부 부담, 무료 대체재(홈택스·삼쩜삼), 기업 복지 예산(B2B) |
| Social | 2539 직장인의 세금 이해 부족, "절약 = 절세" 오해, 카드뉴스형 정보 소비 |
| Technological | 생성형 AI 설명·명세서 사진 인식, 규칙 기반 세액 엔진, 데이터 연동, 앱인토스 미니앱 |

**결론:** 규제는 동시에 바뀌고 있지만, 추가 납부를 겪은 직장인의 **"미리 알고 싶다"는 수요**와 **개인 데이터 연동 확대**가 맞물리는 시기

### 02 경쟁 압력 — 5-Force
| 힘 | 강도 |
|---|---|
| 기존 경쟁자 (삼쩜삼, 은행·카드사 앱, 뱅크샐러드) | 높음 |
| 신규 진입자 (마이데이터 덕분에 핀테크 진입 쉬움) | 중~높음 |
| 대체재 (홈택스 무료 미리보기, 회사 연말정산, 세무사) | 높음 |
| 구매자 교섭력 (무료 대안 많고 갈아타기 쉬움) | 높음 |
| 공급자 교섭력 (홈택스 데이터, 토스 정책 의존) | 중간 |

**결론:** 구조적 난이도 **높음**. 방어 지점은 ① 입력 최소화로 인한 전환 비용 ② 환급금 비례 수수료 없음 ③ 365일 관리 습관

### 03 기회 영역 — 3C
| 축 | 핵심 발견 |
|---|---|
| Customer | 최근 **추가 납부를 경험**했고 올해는 준비하고 싶지만 시작 방법을 모르는 **25~39세 근로소득자** |
| Competitor | 홈택스도 예측·절세 안내를 제공함 → "과거 조회만 한다"는 비교는 불가. 차별화는 **행동 저장 → 실행 점검** |
| Company | 4월 시작·5월 점검의 흐름이 구체적이나, 자동화·반복 이용·지불 의향은 미검증 |

**결론:** 확보할 포지션은 **"4월부터 시작하는 개인별 행동 관리"**

### 04 전략 선택 — SWOT
| | 기회 (O) | 위협 (T) |
|---|---|---|
| **강점 (S)** | **공격 (SO)**: 3~4월 추가 납부 불만 시점에 "행동 1개" 메시지로 소규모 유입 테스트 | **방어 (ST)**: 규칙 엔진 + 출처·가정 표시, "일반 정보 vs 세무 상담" 경계 명시 |
| **약점 (W)** | **보완 (WO)**: 4~5월 코호트로 가설 검증 후 확대, 직접 입력·사진 업로드부터 시작 | **회피 (WT)**: 민감정보 최소 수집, 월별 체크인 가치 검증 후에만 유료 설득 |

## 3. Statement

> **"현재 시장은 ① 추가 납부 경험자의 '미리 알고 싶다'는 수요와 개인 데이터 연동 확대라는 변화가 있고, 경쟁 압력은 ② 홈택스·환급 앱·금융 앱 등 무료 대안이 많고 갈아타기 쉬워 높은 수준이며, 우리는 ③ 규칙 엔진 기반의 신뢰 설계와 수수료 없는 정액 구독 구조라는 역량으로 ④ 최근 추가 납부를 겪은 25~39세 직장인 세그먼트에서 ⑤ '4월 첫 행동 저장 → 5월 점검'으로 이어지는 사전 관리 전략을 선택한다."**

| 빈칸 | 채운 내용 | 출처 |
|---|---|---|
| ① 변화 | 추가 납부 경험자의 사전 관리 수요, 마이데이터·데이터 연동 확대 | PEST |
| ② 경쟁 압력 | 대안 많고 전환 쉬워 높음 | 5-Force |
| ③ 역량 | 규칙 엔진 기반 계산 신뢰, 실제/추정 구분, 환급금 비례 수수료 없음 | SWOT (S) |
| ④ 세그먼트 | 추가 납부 경험이 있는 25~39세 근로소득자 | 3C (Customer) |
| ⑤ 전략 | 4월 시작 → 5월 점검의 행동 관리 (예상액 조회에 그치지 않음) | 3C·SWOT |

**짧은 버전:** *"무료 대안이 많은 시장에서, 추가 납부를 겪은 직장인이 4월에 시작해 5월까지 이어가도록 돕는 행동 관리로 차별화한다."*

## 4. 전략 → 기능 목록·MVP 범위

> 질문: 이 결과가 실제 기능 목록이나 MVP 범위로 정리될 수 있는가? 그저 "멋진 말"에 머물지 않고 목표 달성의 선택 기준으로 작동할 수 있는가?

### 4.1 전략 문장에서 나온 기능 (PRD v3 P0와 대응)
| 전략 요소 | 대응 기능 | 근거 분석 | PRD 우선순위 |
|---|---|---|---|
| 추가 납부 경험자 진입 | 4월 시작 화면, 지난 정산 vs 올해 예상 구분 | PEST·3C | P0 |
| 입력 부담 최소화 (방어 지점) | 자동 채움 확인, 실제/추정 라벨 | 5-Force·SWOT | P0 |
| 4월 첫 행동 저장 | 이번 달 할 일 1개 제안·저장 | 3C·SWOT(SO) | P0 |
| 5월 점검 | 5월 체크인, 저장한 행동 확인 | 3C | P0 |
| 신뢰 (규제·오답 방어) | 자료 부족 상태, 확정 표현 금지, 규칙 엔진 | PEST·SWOT(ST) | P0 |
| 추가 납부 대비 | 경보·대비금 안내 | 3C(고객 구분) | P0 / 상세는 P1 |
| 구독 전환 | 상세 추이·카드 코치·다중 시나리오 | 5-Force(구매자 교섭력) | P1 |

### 4.2 선택 기준으로 쓰는 규칙
새 기능이나 화면을 논의할 때 아래 질문에 답한다.

1. **4월 첫 행동 저장 또는 5월 점검 완료율을 높이는가?** 아니면 P1 이하로 미룬다.
2. **무료 대안(홈택스·삼쩜삼)이 이미 잘하는 일인가?** 그렇다면 따라 하지 않고 "행동 연결"에 집중한다.
3. **입력 부담을 늘리는가?** 늘린다면 자동 채움·사진 업로드로 대체할 수 있는지 먼저 본다.
4. **확정 절세·환급처럼 보일 수 있는 표현인가?** 그렇다면 쓰지 않는다.
5. **추가 소비를 유도하는가?** 유도한다면 제외한다.

### 4.3 이 규칙으로 걸러지는 예
| 아이디어 | 판단 | 이유 |
|---|---|---|
| 12개월 전체 화면 완성 | 보류 (P2) | 4~5월 활성화 검증 전 |
| 금융상품 가입 중개 | 제외 | 규제·PRD 제외 범위 |
| 환급 예상액 크게 보여주기 | 수정 | 확정 표현 위험, 행동 연결이 먼저 |
| 5월 알림 + 저장한 행동 확인 | 채택 | 5월 점검 완료율에 직결 |

## 5. 분석 간 확인이 필요한 부분
| 항목 | 내용 | 조치 |
|---|---|---|
| 토스 데이터 자동 연결 | 5-Force는 이를 **방어 지점**으로 보지만, PRD·3C·PEST는 연동 여부를 **미확정**으로 둠 | 방어 지점이 아니라 *조건부* 방어 지점으로 표현하거나 연동 가능 여부 먼저 확인 |
| 삼쩜삼 수수료 | 5-Force는 "수수료 있음"으로 차별화, 3C는 "제공 범위가 달라 수수료만으로 우열 비교 곤란, 수수료율 확정 안 함" | 발표에서는 3C 기준(확정하지 않음)을 따르는 것이 안전 |
| 365일 관리 | 5-Force 방어 지점이지만 PRD 설계 범위는 4~5월 | "365일 관리"는 방향, MVP는 4~5월임을 구분 |
| 시장 규모 | 3C는 시장 규모 추정을 포함하지 않음, 사업계획은 가정치 | 발표 시 가정치임을 명시 |
