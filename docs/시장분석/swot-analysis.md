## 2. 항목별 근거 (PRD 기준)

### S 강점
| 항목 | 근거 |
|---|---|
| 시점·행동 중심 | 메인 메시지 "또 추가 납부? 올해는 4월부터 바꿔보세요", 4월 첫 방문 → 5월 재방문 여정 (PRD 3장) |
| 낮은 실행 부담 | 홈의 "이번 달, 먼저 확인할 일 1개", 완료 안 하면 완료 처리 안 함, 질책 문구 금지 (5.3, 7장) |
| 신뢰 설계 | "무조건 환급" 금지 표현, 실제값/추정값 구분, 과세연도 표기 분리, 근거 없는 금액 미생성 (1.4, 5.1, 5.2) |
| 비용 신뢰 | 환급금 비례 수수료 없는 정액 구독 (서비스 약속, 11장) |
| 기술 구조 | 세액은 검증된 규칙 엔진, AI는 추출·설명·제안 (10장) |
| 수익 구조 | 무료/프리미엄/체험 구분, 체험 종료 후 무료 체크인 유지 (11장) |

### W 약점
| 항목 | 근거 |
|---|---|

| 데이터 확보 | "자료 연동 가능 여부는 구현 검토 대상", 자동 연동은 제휴·법률 검토 후 (5.1, 10장) |

## 3. 전략 도출 (SWOT 교차)

| | O 기회 | T 위협 |
|---|---|---|
| **S 강점** | **SO (강점으로 기회 잡기)**<br>• 3~4월 추가 납부 불만 시점에 "행동 1개" 메시지로 소규모 광고 테스트<br>• 정액 구독·수수료 없음 메시지를 앱인토스 소개·결제 안내에 신뢰 요소로 활용 | **ST (강점으로 위협 막기)**<br>• 규칙 엔진 + 출처·가정 표시로 계산 오류·과장 표현 리스크 완화<br>• "일반 정보·계산"과 "개별 세무 상담" 경계를 화면 문구로 명확히 표시 |
| **W 약점** | **WO (약점 보완하며 기회 잡기)**<br>• 4~5월 코호트로 가설을 먼저 검증한 뒤 광고 확대<br>• 직접 입력·사진 업로드 MVP로 시작, 연동은 이후 제휴 검토 | **WT (약점·위협 최소화)**<br>• 민감정보 최소 수집, 동의·삭제 흐름을 P0에 포함<br>• 연 1회성 약점은 월별 체크인 가치 검증 후에만 유료 설득 |

## 4. 우선 과제 (제안)

1. **타깃 가설 검증**: 최근 추가 납부 경험자 인터뷰 5~8명, 4월 시작 의향 확인
2. **재방문 설계 검증**: 4월 프로토타입 → 5월 점검 흐름 과업 테스트 (저장한 행동 찾기·완료 표시)
3. **데이터 경로 확정**: 직접 입력/사진 업로드/연동 중 MVP 범위 결정
4. **계산 규칙 책임자 지정**: 과세연도별 공제율·한도 검증 및 갱신 담당
5. **경쟁 서비스 비교표 작성**: 삼쩜삼 기존 연말정산 미리보기, 홈택스, 토스 등과 기능·시점·가격 비교
6. **법적 경계 문구 확정**: 세무 자문이 아님을 알리는 화면·약관 문구

## 5. 문서 간 확인이 필요한 부분
- PRD 페르소나는 **김지우 29세, 추가 납부 42만원**이고, `persona-tax-saving.md`의 지우는 **26세, 추가 납부 약 100만원**입니다. 발표 자료에서 어느 쪽을 쓸지 정하거나 서로 다른 목적(PRD=디자인 시나리오, 페르소나 문서=절세 효과 시뮬레이션)임을 구분해야 합니다.
- PRD는 금융상품 추천을 제외하지만, `persona-tax-saving.md`는 연금저축·IRP 활용을 절세 방법으로 제안합니다. 상품 판매·가입 중개가 아닌 **일반 정보**로 설명하는지 정책을 맞춰야 합니다.
- 사업계획 README는 5가지 기능(정부 혜택 탐색 포함)을 말하지만, PRD v3는 정부지원금 추천을 **제외**합니다.
