# 3C 분석 | AI 기반 연말정산 사전 관리 플랫폼

**작성일:** 2026.11.05  
**기준 문서:** PRD v3  
**대표 시나리오:** 3월 추가 납부 확인 → 4월 관리 시작 → 5월 실행 점검  
**분석 기준:** PRD와 공식 공개 자료. 고객 심리·이용 의향은 조사 전 가설이며, 자사 강점은 기획 단계의 잠재력으로 평가한다.

> 핵심 경쟁력은 ‘AI로 예상 세금을 계산한다’보다 ‘추가 납부를 경험한 사용자가 4월에 관리를 시작하고, 5월에도 실행을 이어가게 한다’에 있다.

## 1. Customer — 고객 분석

### 1.1 핵심 고객

**최근 추가 납부를 경험했고, 올해는 준비하고 싶지만 시작 방법을 모르는 25~39세 근로소득자.**

연령보다 ‘추가 납부 경험’과 ‘관리 시작 의향’을 우선 선별한다. 추가 납부 확인 시기는 회사별로 다르므로 모든 사용자가 3월에 확인한다고 전제하지 않는다.

| 분석 항목 | 고객의 상황·욕구 | 서비스에 필요한 대응 |
|---|---|---|
| 이용 계기 | 예상하지 못한 추가 납부로 생활비 부담을 느낌 | 지난 결과를 올해 준비로 연결 |
| 기능적 욕구 | 왜 추가 납부했는지, 올해 무엇을 바꿀 수 있는지 알고 싶음 | 자료에 근거한 원인 설명과 적용 가능한 행동 |
| 감정적 욕구 | 다음에도 갑자기 돈이 나갈까 불안함 | 현재 상황과 준비 방법을 이해하도록 지원 |
| 행동 장벽 | 세금 용어·자료 준비·반복 입력이 번거로움 | 자동 채움과 변경 사항 확인 |
| 재방문 이유 | 지난달 계획을 실행했는지 확인하고 싶음 | 저장한 행동을 다음 달 점검과 연결 |
| 결제 장벽 | 무료 계산 도구가 있는데 구독할 이유가 약함 | 지속 관리가 주는 구체적인 편익 증명 |

### 1.2 고객 세분화

| 세부 고객 | 필요한 도움 | 우선순위 |
|---|---|---|
| 적용 가능한 공제·변경 사항을 놓친 사용자 | 누락 점검과 실행 안내 | 높음 |
| 세금을 더 줄일 여지는 작지만 납부 부담이 큰 사용자 | 예상액 확인과 대비 계획 | 높음 |
| 자료가 복잡한 이직·복수소득 사용자 | 정보 통합과 정확한 계산 | 초기 지원 범위 검토 |
| 불만은 있지만 관리할 의향이 없는 사용자 | 적은 노력으로 얻는 첫 효용 | 유입 후 활성화 검증 |

추가 납부가 곧 절세 실패를 의미하지는 않는다. 국세청에 따르면 정산 시 납부·환급액은 확정된 세금과 이미 납부한 세금의 차이를 반영한다. 따라서 **세금 자체를 줄이고 싶은 고객과 갑작스러운 현금 지출을 피하고 싶은 고객을 구분**해야 한다. [국세청 근로소득 안내](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7870&mi=6590)

### 1.3 시기별 고객 과업

| 시기 | 고객 질문 | 핵심 과업 |
|---|---|---|
| 결과 확인 직후 | 왜 더 냈지? 올해는 어떻게 준비하지? | 지난 결과와 올해 준비 구분 |
| 4월 첫 방문 | 내가 지금 할 수 있는 일이 있나? | 올해 예상 확인과 행동 1개 저장 |
| 5월 재방문 | 지난달 계획대로 했나? | 실행 여부 점검과 실제 자료 보완 |
| 이후 | 상황이 달라졌나? | 변경 사항 확인과 필요한 행동 갱신 |

**시사점:** 4월 첫 화면은 예상 금액과 함께 ‘지금 할 수 있는 일’에 답해야 한다. 5월에는 새로운 정보를 늘어놓기보다 지난 행동의 실행 여부를 먼저 확인한다.

## 2. Competitor — 경쟁 분석

경쟁 범위는 연말정산 앱뿐 아니라 공식 계산 도구, 환급 서비스, 금융 플랫폼, 검색과 방치까지 포함한다.

### 2.1 경쟁·대체재 비교

| 경쟁·대체재 | 고객이 선택하는 이유 | 확인된 제공 가치 또는 대체 방식 | 자사 대응 방향 |
|---|---|---|---|
| 홈택스 연말정산 미리보기 | 공식 정보에 대한 신뢰 | 예상 세액 계산, 예정 지출 반영, 공제 관련 안내, 과거 추이 | 계산 이후 행동 저장·실행 점검에 집중 |
| 삼쩜삼 | 환급 가능 금액을 간편하게 확인하려는 목적 | 공식 홈페이지에서 환급액 조회를 핵심 진입 행동으로 제시 | 올해 관리와 다음 정산 준비라는 목적을 명확히 전달 |
| 토스·뱅크샐러드 등 금융 플랫폼 | 익숙한 금융 이용 환경 | 금융 서비스 접근성·상품 비교 등 기존 접점 | 사용자가 별도 서비스를 쓸 이유를 구체화 |
| 회사 담당자·세무 전문가 | 상황에 맞는 설명과 신뢰 | 개별 상황 확인과 상담이라는 대체 경로 | 일상적인 점검을 담당하고 복잡한 상황은 연결 |
| 검색·영상·커뮤니티 | 비용 없이 빠르게 정보를 얻음 | 일반적인 절세 정보 탐색 | 내 조건에 적용되는지 판단하는 부담을 줄임 |
| 아무것도 하지 않기 | 시간과 노력이 들지 않음 | 당장의 번거로움 회피 | 짧은 확인만으로 얻는 효용 증명 |

회사 상담, 검색, 방치는 고객의 대체 행동에 대한 분석이며 특정 사업자의 기능 조사 결과가 아니다.

### 2.2 확인된 사실과 해석

**홈택스도 사전 예측과 절세 안내를 제공한다.** 2025년 귀속 공식 안내에는 카드 사용액·예상 지출 반영, 공제항목 수정, 최근 3년 추이 확인이 포함된다. 따라서 ‘기존 서비스는 과거 조회만 한다’는 비교는 수정해야 한다. 이 자료는 해당 연도의 제공 기능 근거이며, 다음 연도 운영 일정까지 의미하지 않는다. [국세청 미리보기 안내](https://www.korea.kr/news/policyNewsView.do?newsId=148954467)

**삼쩜삼은 환급 조회를 전면에 내세운다.** 자사는 신고·환급 처리 도움 서비스와 제공 범위가 다르므로 수수료만으로 우열을 비교하기 어렵다. 이번 분석에서는 구체 이용료나 수수료율을 확정하지 않는다. [삼쩜삼 공식 홈페이지](https://www.3o3.co.kr/)

**뱅크샐러드는 금융상품 데이터와 조건을 활용한 비교·매칭을 강조한다.** 이런 플랫폼과의 경쟁에서는 금융정보를 쉽게 보여준다는 것만으로 충분한 차이가 되기 어렵다는 것이 분석상 판단이다. 토스·뱅크샐러드의 연말정산 세부 기능과 운영 시기는 별도 확인이 필요하며, 확인되지 않은 기능을 제공 또는 미제공으로 단정하지 않는다. [뱅크샐러드 공식 홈페이지](https://www.banksalad.com/)

### 2.3 경쟁상 기회

**확보할 포지션은 ‘4월부터 시작하는 개인별 행동 관리’다.**

- 예상 결과를 확인한 뒤 적용 가능한 행동을 선택한다.
- 행동을 저장하고 다음 점검 시점을 정한다.
- 다음 달 실제 자료와 실행 여부를 확인한다.
- 적용 가능한 행동이 없으면 현황 유지와 대비를 안내한다.

경쟁사가 이 경험을 전혀 제공하지 않는다는 근거는 아직 없다. 따라서 독점적 차별점이 아니라 검증할 차별화 가설로 다룬다.

## 3. Company — 자사 분석

현재 자사는 운영 성과가 검증된 서비스가 아닌 PRD 단계다. 기획의 장점과 실제 확보한 역량을 분리한다.

| 항목 | 기획상 강점 | 약점·위험 | 필요한 대응 |
|---|---|---|---|
| 타깃 | 추가 납부 경험이라는 선명한 계기 | 불만이 실제 이용으로 이어질지 미확인 | 경험자 대상 유입·행동 테스트 |
| 시점 | 4월 시작·5월 점검으로 흐름이 구체적 | 4월까지 관심이 유지되지 않을 수 있음 | 결과 확인 직후와 4월 진입 비교 |
| 개인화 | 이번 달 할 일 1개로 실행 부담 축소 | 매월 유효한 행동이 없을 수 있음 | 현황 유지·추가 행동 없음 상태 제공 |
| 자동화 | 정보 입력 부담을 줄이는 방향 | 연동 미확정, 사진 인식·추정 오류 가능 | 실제 자료와 추정의 명확한 구분 |
| 반복 이용 | 저장한 행동과 다음 점검 연결 | 점검 자체를 귀찮게 느낄 수 있음 | 짧은 체크인과 변화가 있을 때의 알림 |
| 수익 | 고정 구독료로 비용 구조 설명 가능 | 무료 대체재 대비 지불 이유가 약함 | 관리 시간·누락 방지 등 체감 가치 검증 |
| 유통 | 앱인토스로 설치 부담 완화 가능 | 노출·데이터 접근을 보장받지 못함 | 자체 유입과 플랫폼 요건 확인 |

### 3.1 유통 채널 평가

토스 공식 설명상 미니앱은 별도 설치 없이 실행할 수 있다. 다만 홈 추천 등 노출 범위는 사용자 반응과 완성도에 따라 달라지므로 **입점 자체를 사용자 확보 역량으로 보기는 어렵다.** [토스 미니앱 안내](https://toss.im/tossfeed/article/toss_miniapp_qna), [미니앱 노출 정책 안내](https://toss.im/apps-in-toss/blog/mini-app-exposure-faq?slugOrId=discountspot)

토스 안에서 실행되는 것과 토스의 금융 데이터를 자동으로 이용할 수 있는 것은 별개다. 실제 데이터 제공 범위는 구현 전 확인해야 한다.

### 3.2 우선 확보할 역량

1. **계산 신뢰:** 과세연도별 규칙 검증, 실제·추정값 구분, 계산 근거 표시.
2. **행동 적합성:** 사용자에게 적용 가능한 행동만 제안하고 완료한 행동은 반복하지 않기.
3. **실행 연결:** 행동 저장 → 확인 시점 → 완료·미완료 점검의 연결.
4. **입력 편의:** 자료 연동이 불가능해도 최소 입력·사진 업로드로 진행.
5. **성과 해석:** 단순 예상액 변화를 실제 절세 성과나 앱의 기여로 단정하지 않기.

**시사점:** AI라는 기술보다 자료 확인 → 적용 가능한 행동 → 실행 기록 → 다음 점검의 완성도가 중요하다. 특히 4월은 미래 추정 비중이 크므로 계산 근거와 불확실성을 이해할 수 있어야 한다.

## 4. 3C 종합 전략

| 3C에서 발견한 점 | 제품·디자인 결정 |
|---|---|
| 고객은 예상액보다 시작 방법을 모름 | 홈에 이번 달 할 일 1개를 예상액과 함께 배치 |
| 공식 서비스도 예측·절세 안내를 제공 | 행동 저장과 다음 달 실행 점검을 핵심 경험으로 설계 |
| 추가 납부 원인이 사용자마다 다름 | 절세 점검과 납부 대비를 분기 |
| 자동화 역량이 아직 미확정 | 자료 부족·추정 포함·연동 실패 화면을 기본 흐름에 포함 |
| 반복 이용과 결제 의향이 미검증 | 광고 확대보다 4월 활성화 → 5월 점검 완료를 먼저 검증 |

### 권장 포지셔닝

> 추가 납부를 경험한 직장인이, 4월부터 자기 상황에 맞는 준비를 시작하고 매월 점검하도록 돕는 연말정산 관리 서비스.

### 먼저 검증할 질문

| 검증 질문 | 확인할 행동·지표 |
|---|---|
| 추가 납부 경험자가 실제로 4월에 관리를 시작하는가? | 첫 계산 완료율, 첫 행동 저장률 |
| 예상액을 본 뒤 제안된 행동을 실행하는가? | 행동 완료 확인율, 미실행 사유 |
| 그 행동을 점검하기 위해 5월에 돌아오는가? | 4월 활성화 사용자 중 5월 체크인 완료율 |
| 무료 도구 대신 구독할 이유가 있는가? | 체험 후 전환율, 지불 의향과 이유 |
| 입력 최소화가 실제로 작동하는가? | 완료 시간, 정보 수정률, 자료 준비 단계 이탈률 |

목표 수치는 초기 기준선을 측정한 뒤 확정한다. 특히 유지율은 가입 월·무료/체험/유료·실제값/추정값 상태로 나눠 해석한다.

## 5. 분석 한계

- 고객 욕구와 4월 시작 의향은 인터뷰·행동 데이터로 검증되지 않았다.
- 경쟁 비교는 공개 공식 자료 중심이며 각 앱의 전체 화면을 직접 검증한 결과가 아니다.
- 자료에서 확인하지 못한 기능은 미제공으로 단정하지 않았다.
- 세법·플랫폼 정책·경쟁 기능은 실제 출시 전에 다시 확인한다.
- 이 문서는 시장 규모 추정이나 개인별 세무 자문을 포함하지 않는다.
