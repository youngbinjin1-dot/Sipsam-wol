## 정해진 것

서비스를 '4월부터 1년 관리'에서 '11~12월에 바로 써보는 체험형'으로 옮기고, 그 수요를 페이크 도어 테스트로 먼저 확인하기로 했다.

- **데이터:** 홈택스 캡처 대신 토스 연동으로 카드 사용액·월급·월세를 가져온다. 나머지 정보는 터치 한 번으로 끝나는 질문 카드로 받는다.
- **핵심 기능:** 월급에 맞춘 카드 사용 슬라이더(신용·체크를 얼마나 쓰면 세금이 얼마나 줄어드는지 보여주는 조절 막대), 신용카드 문턱을 넘으면 체크카드로 바꾸라는 전환 알림.
- **수익 흐름:** 11~12월 무료 체험 → 1월 연말정산 도우미와 구독 할인으로 유도. '환급금에서 떼지 않음'을 설득 포인트로 유지.
- **테스트 방식:** 인스타 카드뉴스 → 랜딩페이지(서비스 소개 한 장짜리 웹페이지) → 이메일 사전 신청. 필수 입력은 이메일 하나, 결제 정보는 받지 않는다.
- **문서 기준:** main의 `prd.md`가 11월 시즌 버전이 됐다. 도은의 `prd-11월.md`와 내용이 완전히 같다.

## KPT 회고

KPT는 Keep(잘해서 계속할 것), Problem(문제였던 것), Try(다음에 해볼 것)로 나눠 돌아보는 방식이다. 아래는 저장소 기록에서 보이는 것만 적었고, 각자 느낀 점은 덧붙여 주세요.

### Keep

- 기획 문서(PRD·intent)가 먼저 나오고, 10분쯤 뒤 그 문서를 기준으로 MVP 화면이 나왔다. 문서 → 화면 순서가 잘 지켜졌다.
- intent 문서에 '판단 원칙'과 '하지 않을 것'을 적어 둬서, 화면을 만들다 헷갈릴 때 돌아올 기준이 생겼다.
- 작업마다 브랜치를 나누고 PR로 합쳐서 누가 무엇을 바꿨는지 기록이 남았다.

### Problem

- **같은 PRD가 두 갈래로 올라감.** 도은의 `prd-update` 브랜치 `prd-11월.md`와 같은 내용이 siney의 PR #32로 main `prd.md`에 들어갔다. 지금 `prd-update`를 그대로 합치면 `prd.md`가 예전 v3로 되돌아갈 수 있다.
- **페이크 도어 원칙과 MVP 랜딩이 어긋남.** 의도 문서는 '토스 이름·로고 쓰지 않기', '이메일 사전 신청 받기'인데, MVP 랜딩 문구는 '토스가 이미 알고 있어요'이고 연락처를 받지 않고 브라우저 클릭 기록만 남긴다.
- **`index.html`이 두 개.** main의 `index.html`은 앱 모의실행이고, `dulnaeyo-mvp`의 `index.html`은 페이크 도어 랜딩이다. GitHub Pages(저장소를 웹사이트로 띄워주는 기능)로 배포하면 어느 게 첫 화면이 될지 헷갈린다.
- 1시간 동안 브랜치가 여러 개 생겼고, 아직 3개가 합쳐지지 않았다.

### Try

- 같은 파일을 고칠 때는 시작 전에 단톡 등에 '지금 ○○ 파일 작업 중'이라고 한 줄 남기기.
- 페이크 도어 랜딩을 `intent-fakedoor-test.md` 기준에 맞추기: 토스 표현 빼기, 이메일 칸 + 개인정보 동의 넣기.
- 랜딩과 앱 모의실행의 파일 이름·위치를 정해서 첫 화면을 하나로 정리하기.
