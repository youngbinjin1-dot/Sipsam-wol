## F1. 토스 데이터 연동·동의 (S01)

### 요구사항
- R1.1 사용할 데이터 3종을 항목별로 보여준다: ① 카드 결제 내역(신용/체크 구분, 업종) ② 급여 계좌 입금 내역 ③ 정기 이체 내역
- R1.2 각 항목에 **이용 목적, 보관 기간, 철회 방법**을 한 줄씩 표시한다.
- R1.3 필수 동의(①②③)와 **선택 동의(민감정보: 의료비 등)**를 분리한다. 선택 동의는 기본 꺼짐.
- R1.4 “동의 안 하고 직접 입력할게요” 링크를 둔다 → F1-E1.

### 수용 기준
- Given 사용자가 S01에 진입했을 때, When 필수 동의 없이 [동의하고 시작]을 누르면, Then 버튼은 비활성 상태이고 넘어가지 않는다.
- Given 선택 동의를 하지 않았을 때, Then 의료비 관련 질문 카드(Q6)는 노출되지 않고, 해당 항목은 계산에서 빠지며 결과에 “의료비 제외” 라벨이 붙는다.

### 예외
- **F1-E1 연동 거부:** 직접 입력 3개(연봉, 올해 카드 사용액 대략, 월세 여부)만 받고 S04로 간다. 신용/체크 비율은 50:50으로 가정하고 “직접 입력 기준” 라벨을 붙인다.
- **F1-E2 연결된 카드 없음:** “토스에 연결된 카드가 없어요” + [카드 연결하기] / [직접 입력할게요]

## F2. 자동으로 찾은 정보 (S02)

### F2-1 카드 사용액 분류

| 분류 | 기준 (업종 코드 기반) | 공제율 |
|---|---|---|
| 제외 | 국세·지방세, 공과금(전기·수도·가스·관리비), 통신요금, 보험료, 해외결제·면세점, 상품권·기프트카드, 자동차 구입(중고차 10% 제외), 금융 수수료·이자 등 | 0% |
| 일반 (신용) | 위 외 신용카드 결제 | 15% |
| 일반 (체크·현금영수증) | 위 외 체크카드·현금영수증 | 30% |
| 전통시장·대중교통 | 해당 업종 | 40% |
| 도서·공연·문화 등 | 해당 업종, 총급여 7천만 원 이하만 | 30% |

- R2.1 기간: 올해 1월 1일 ~ 어제
- R2.2 업종이 불분명한 결제는 “일반”으로 넣고 분류 신뢰도 ‘낮음’으로 저장한다.
- R2.3 S02에는 합계만 보여준다: “올해 카드 사용 ○○만 원 (공제 대상 ○○만 원 · 제외 ○○만 원)” + [자세히 보기]
- R2.4 모든 금액 옆에 “추정” 라벨.

### F2-2 총급여 추정
- R2.5 최근 3개월 급여 입금액(같은 입금처에서 매달 비슷한 날짜에 들어온 가장 큰 입금)의 평균 = 월 실수령액
- R2.6 월 실수령액 → 세전 월급 역산(간이세액표·4대보험 기준 계산 엔진) → × 12 = 추정 총급여 (만 원 단위 반올림)
- R2.7 질문 카드 Q1에서 확인. 사용자가 수정하면 수정값을 우선한다.
- **예외 F2-E1:** 급여 입금을 찾지 못하면 Q1을 “연봉을 알려주세요”(숫자 입력, 범위 1,000만~2억)로 바꾼다.

### F2-3 월세 후보
- R2.8 같은 받는 사람에게 3개월 이상 매달 비슷한 금액(±5%)·비슷한 날짜(±5일)로 보낸 이체 중 20만~300만 원 → 월세 후보
- R2.9 후보는 최대 1개(금액이 가장 큰 것). Q2에서 확인.

## F3. 터치 한 번 질문 카드 (S03)

| ID | 질문 | 선택지 | 조건 | 다음 단계 |
|---|---|---|---|---|
| Q1 | 연봉 약 ○○만 원 맞나요? | 맞아요 / 고칠래요 | 항상 | 고칠래요 → 숫자 입력 |
| Q2 | 매달 ○○님께 보내는 ○○만 원, 월세인가요? | 네 / 아니요 | 월세 후보 있을 때 | 네 → Q2-1 |
| Q2-1 | 지금 사는 집으로 전입신고 했나요? | 네 / 아니요 / 모르겠어요 | Q2=네 | — |
| Q3 | 집이 있으신가요? | 있어요 / 없어요 / 모르겠어요 | 항상 | — |
| Q4 | 세대주인가요? | 네 / 아니요 / 모르겠어요 | Q3=없어요 | — |
| Q5 | 같이 사는(또는 부양하는) 가족이 있나요? | 있어요 / 없어요 | 항상 | 있어요 → 인원 +/− (부모·자녀·기타) |
| Q6 | 올해 병원비가 많이 나왔나요? | 네 / 아니요 | 민감정보 선택 동의 시 | 네 → 금액대 4단계 선택 |

### 요구사항
- R3.1 한 화면에 질문 1개. 상단 진행 바(“2/5”).
- R3.2 각 질문은 **기본값을 미리 선택**해 둔다 (Q1=추정값, Q3·Q5=“없어요”는 기본 선택하지 않음 — 사실 확인이 필요한 질문은 기본값 없이).
- R3.3 “모르겠어요” 선택 시 해당 공제는 0으로 계산하고, 1월 도우미 체크리스트에 자동 추가한다.
- R3.4 뒤로 가기로 이전 답 수정 가능.
- R3.5 월세 세액공제는 Q2=네, Q2-1=네, Q3=없어요, Q4=네, 총급여 ≤ 8,000만 원일 때만 계산에 넣는다. 하나라도 “모르겠어요”면 “월세 공제 확인 필요” 상태로 계산에서 빼고 결과에 안내한다. (주택 규모 요건은 1월 도우미에서 확인)

### 수용 기준
- 대부분의 사용자(월세·가족·병원비 없음)는 **S01 동의 1 + Q1 1 + Q3 1 + Q4 1 + Q5 1 = 터치 5번**으로 S04에 도착한다.
- Given Q2를 “아니요”로 답하면, Then Q2-1은 나오지 않는다.

## F4. 올해 예상 결과 (S04)

### 표시 요소
1. 큰 숫자: “2026년 귀속 예상 **추가 납부 ○○만 원**” 또는 “예상 **환급 ○○만 원**”
2. 라벨: “추정 · ○월 ○일 기준”
3. 작년 비교(작년 결과가 있을 때만): “작년(2025년 귀속) 추가 납부 42만 원”
4. 카드 공제 문턱 진행 바: “문턱까지 ○○만 원” 또는 “문턱 넘음”
5. 빠진 항목 안내: “월세 공제 확인 필요”, “의료비 제외” 등
6. 고지 문구: “참고용 예상치이며 세무 상담이 아니에요.”
7. CTA: [남은 두 달 계획하기] → S05

### 계산
- 예상 결정세액 − 추정 기납부세액 = 예상 추가 납부(+) / 환급(−)
- 12월 31일까지의 카드 사용액은 “최근 3개월 월평균 × 남은 일수/30”으로 가정 (S05에서 사용자가 바꾸면 갱신)
- 계산은 서버의 규칙 기반 계산 엔진이 한다. AI는 숫자를 만들지 않는다.

### 예외
- 필수 값(총급여) 없음 → 금액 대신 “연봉을 알려주시면 계산할 수 있어요” + 입력 버튼

## F5. 카드 사용 슬라이더 (S05) ★

### 5.1 입력값

| 값 | 기본값 | 범위 | 단위 |
|---|---|---|---|
| `spent` 올해 공제 대상 사용액 (어제까지) | F2 결과 | 고정 (수정 불가, 자세히 보기만) | 원 |
| `credit_spent` / `debit_spent` | F2 결과 | 고정 | 원 |
| `plan_total` 12/31까지 쓸 예정 금액 | 최근 3개월 월평균 × 남은 일수/30 (만 원 반올림) | 0 ~ max(기본값×3, 300만) | 1만 원 |
| `plan_debit_ratio` 그중 체크카드 비율 | 추천값 | 0 ~ 100% | 5% |
| `big_items[]` 큰 지출 | 없음 | 항목당 1만~2,000만 | 1만 원 |

### 5.2 계산 규칙 (설계 기준값)

```
T = 총급여 × 0.25                         # 문턱
credit_total = credit_spent + plan_total × (1 − plan_debit_ratio) + big_items(신용)
debit_total  = debit_spent  + plan_total × plan_debit_ratio       + big_items(체크)
special      = 전통시장·대중교통 사용액 (실적 + 계획의 같은 비율 추정)
culture      = 도서·공연 등 (총급여 7천만 원 이하만)

# 문턱은 신용카드 사용분부터 먼저 채운다
남은문턱 = T
c = max(credit_total − 남은문턱, 0); 남은문턱 = max(남은문턱 − credit_total, 0)
d = max(debit_total − 남은문턱, 0);  남은문턱 = max(남은문턱 − debit_total, 0)
s = max(special − 남은문턱, 0) ...   (이후 순서 동일)

기본공제 = min(c×0.15 + d×0.30 + culture분×0.30, 기본한도)
추가공제 = min(s×0.40 (+ 기본한도 넘친 문화분), 추가한도)
공제액 = 기본공제 + 추가공제

기본한도 = 300만 원 (총급여 ≤ 7천만) / 250만 원 (초과)   ※ 자녀 수 등에 따른 상향 여부 2026 귀속 확인
예상 세금 감소액 = 공제액 × 한계세율 × 1.1
한계세율: 과세표준 1,400만 이하 6% / 5,000만 이하 15% / 8,800만 이하 24% / 1.5억 이하 35% ...
```

- R5.1 슬라이더를 움직이면 **100ms 안에** 결과가 바뀐다 (위 간이 계산은 화면에서 바로, 저장 시 서버 엔진으로 재계산).
- R5.2 화면에 보여주는 값: ① 문턱 진행 바 ② 신용/체크 금액 ③ **예상 추가 납부 변화(전 → 후)** ④ **예상 세금 감소액** ⑤ 추천 문구
- R5.3 공제액은 [계산 방법 보기] 안에만 보여준다. 메인 숫자는 세금 감소액.

### 5.3 추천 비율 알고리즘

| 상태 | 조건 | 추천 | 문구 |
|---|---|---|---|
| A 문턱 전 | spent < T | 남은문턱까지는 신용, 나머지 체크 → `plan_debit_ratio = max(plan_total − (T − spent), 0) / plan_total` | “○○만 원까지는 신용카드, 그다음부터 체크카드가 유리해요.” |
| B 문턱 넘음 | spent ≥ T, 한도 미달 | 체크 100% | “이미 문턱을 넘었어요. 남은 기간은 체크카드가 유리해요.” |
| C 한도 도달 | 기본공제가 한도에 도달 | 비율 무관 | “카드 공제 한도를 다 채웠어요. 남은 기간은 혜택 좋은 카드를 써도 돼요. 전통시장·대중교통은 추가 공제가 있어요.” |
| D 문턱 못 넘음 | spent + plan_total < T | 비율 무관 | “올해는 문턱까지 ○○만 원이 남아 카드 공제가 어려워요. 결제 수단은 편한 걸로 쓰세요.” |

- R5.4 [추천대로 맞추기] 버튼은 `plan_debit_ratio`를 추천값으로 바꾼다.
- R5.5 **상태 D에서는 “문턱을 넘기려면 더 쓰세요” 같은 문구를 절대 보여주지 않는다.**

### 5.4 표현 규칙
- 슬라이더 1 라벨: “12월 31일까지 쓸 예정 금액” (금지: “더 쓸 금액”, “추가 사용”)
- 슬라이더 1 아래 고정 안내: “더 쓰면, 쓴 돈보다 아끼는 세금이 훨씬 적어요.”
- 결과 아래 고정 안내: “카드 포인트·할인 혜택은 계산에 넣지 않았어요.”
- 특정 카드 상품명 노출 금지.

### 5.5 접근성
- 슬라이더 옆에 금액 직접 입력 필드 제공 (손이 불편하거나 정밀 조정이 필요한 사용자).
- 스크린리더: “신용카드 80만 원, 체크카드 120만 원, 예상 세금 감소 3만 원” 형식으로 값 읽기.
- 색만으로 상태를 구분하지 않는다 (진행 바에 숫자 함께 표시).

### 5.6 저장 (S06)
- R5.6 [이 계획으로 저장할게요] → CardPlan 저장 → S06에서 문턱 알림 켜기(기본 켜짐 아님, 사용자가 켬)

### 수용 기준
- Given 총급여 4,200만 원, spent 900만 원(전부 신용), plan_total 200만 원일 때, When [추천대로 맞추기]를 누르면, Then 신용 150만 원·체크 50만 원으로 바뀌고 문구는 “150만 원까지는 신용카드, 그다음부터 체크카드가 유리해요.”
- Given spent ≥ T일 때, Then 추천은 체크 100%이고 상태 B 문구가 나온다.
- Given 슬라이더 1을 올려도, Then “더 쓰세요” 계열 문구는 어떤 상태에서도 나오지 않는다.

## F6. 결제 수단 전환 알림 (S07)

### 이벤트 규칙

| ID | 이벤트 | 조건 (매일 새벽 결제 데이터 갱신 후 판정) | 채널 | 발송 |
|---|---|---|---|---|
| N1 문턱 임박 | 남은문턱 ≤ 최근 3개월 월평균 지출 | 푸시 | 1회 |
| N2 **문턱 도달** | spent ≥ T 가 처음 참이 된 날 | 푸시 + 다음 앱 진입 시 S07 바텀시트 | 1회 |
| N3 한도 도달 | 기본공제 ≥ 기본한도 가 처음 참 | 푸시 | 1회 |
| N4 계획 이탈 | 지난 7일 신용 비율이 저장한 계획보다 20%p 이상 높음 (상태 B일 때만) | 앱 내 카드 | 주 1회 이하 |

### 요구사항
- R6.1 푸시는 사용자가 S06 또는 설정에서 **알림을 켠 경우에만** 보낸다.
- R6.2 전체 푸시는 **주 2회 이하.** 같은 이벤트는 다시 보내지 않는다.
- R6.3 푸시 본문에 금액(세금·연봉)을 넣지 않는다. 예: “카드 공제 문턱을 넘었어요. 이제부터는 체크카드가 유리해요.”
- R6.4 S07 바텀시트: 제목, 한 줄 설명(“남은 기간 체크카드로 ○○만 원 결제하면 세금이 약 ○만 원 줄어요 · 추정”), [알겠어요] [계획 다시 보기]. 아래로 쓸어 닫기 가능.
- R6.5 12월 31일 이후에는 N1~N4를 보내지 않는다.
- R6.6 진입 시점에 이미 문턱을 넘은 사용자에게는 N2를 푸시로 보내지 않고 S04·S05에서 바로 상태 B로 안내한다.

### 수용 기준
- Given 알림을 끈 사용자, When 문턱을 넘어도, Then 푸시는 가지 않고 다음 앱 진입 시 홈 카드로만 알린다.
- Given N2를 이미 받은 사용자, Then 같은 해에 N2는 다시 오지 않는다.

## F8. 1월 구독 안내·결제 (S09, S10)

- R8.1 노출: 1월 1일 ~ 특별가 마감일. 진입 경로 = 마무리 리포트, 홈 배너, 1월 알림(알림 동의자만).
- R8.2 S09 필수 표시: 구독 혜택(1월 연말정산 도우미, 2~3월 결과 비교, 2027 연중 관리), **특별가 금액·적용 기간·첫해 한정·갱신 가격**, “환급금에서 한 푼도 떼지 않아요” + 구독료.
- R8.3 S10 필수 표시: 결제 금액, 결제일, 갱신일·갱신 가격, 해지 방법. **유료 결제 동의 체크박스는 별도, 기본 꺼짐.**
- R8.4 체험 기간(11~12월)에는 결제 수단을 받지 않는다. 자동 결제 없음.
- R8.5 구독하지 않은 사용자는 무료 플랜(예상 결과 조회, 추가 납부 경보)으로 유지, 데이터 보존.
- R8.6 정가 표시(“정가 ○원 → 특별가 ○원”)는 그 정가가 실제로 판매되거나 특별가 기간 후 실제 적용되는 가격일 때만 쓴다.
- R8.7 특별가 마감일이 지나면 “마감 임박” 문구를 즉시 내린다.

## F9. 1월 연말정산 도우미 (S11~S13)

| 단계 | 요구사항 |
|---|---|
| ① 준비 | 간소화 서비스 오픈일(국세청 공지 기준) D-day, 회사 마감일 입력, 체크리스트 자동 생성 (F3에서 “모르겠어요” 답한 항목 포함) |

| ③ 부양가족 | 가족별 나이·소득 요건 질문 (예/아니요/모르겠어요), 형제자매 중복 공제 주의 안내 |
| ④ 최종 예상 | 간소화 값으로 재계산, 11월 예상 대비 변화 |

| ⑥ 추가 납부 대비 | 2월 예상 공제액, 분납은 “조건에 해당하면 회사를 통해” 수준 + 국세청 안내 링크 |

- R9.1 도우미는 서류를 **대신 작성·제출하지 않는다.** 버튼 문구에 “제출하기” 금지, “체크 완료” 사용.
- R9.2 “이 공제 받으세요/받지 마세요” 같은 개인 판단 문구 금지. 애매한 항목은 “회사 담당자 또는 세무사에게 확인하세요”.
- R9.3 업로드한 PDF 원본은 읽은 뒤 폐기하고, 추출한 값만 저장한다.

## 12. 비기능 요구사항

- **성능:** 슬라이더 재계산 100ms 이내, S04 결과 표시 2초 이내.
- **정확성:** 계산 엔진은 연도별 규칙 버전을 저장하고, 결과마다 사용한 버전을 기록한다.
- **개인정보:** 최소 수집, 민감정보 분리 저장, 동의 철회 시 해당 데이터 삭제, 업로드 원본 폐기.
- **접근성:** 대비 4.5:1 이상, 슬라이더 직접 입력 대안, 스크린리더 라벨.
- **문구:** 모든 금액 화면에 과세연도·“추정” 표시.
